## 完了報告の作法

- PR の URL とマージ済みであること、`check_branches.sh` の結果（main と dev-claude だけ）を必ず書く
- 「後でまとめて」はしない。依頼ごとに PR → マージ → dev-claude を main に追従 → 報告
- **main が Actions の再ビルド（`chore(build): dist/ を再ビルド`）で進んでいることが多い**。コミット前に `git fetch` して、dist を一旦 `git checkout -- dist && git clean -fd dist` で戻し、ソースだけコミット → `git rebase origin/main` → `npm run build` → dist をコミット、の順が安全
- **別のセッションが同じ dev-claude を同時に使うことがある**（10/26 に PR #116 が別セッションから出た）。未検査の記事を dev-claude に push すると別セッションが main に入れてしまう恐れがあるので、エージェントの執筆途中のファイルは push しない。並行作業なら `dev-claude-<name>` を切る
